# Multi-Agent Workspace v0.3.0 — 完整设计规格

> 日期: 2026-05-28
> 状态: 设计中
> 目标: 基于现有 MVP 重构，实现完整的多 Agent 协作平台

---

## 1. 产品定位

**一句话定位**: 面向学生、个人开发者和技术爱好者的本地优先多 AI Agent 协作工作台，帮助他们通过 Agent 团队完成科研、小工具开发和软件工程项目。

**目标用户**:
- 学生: 用多 Agent 辅助论文写作、实验设计、文献综述
- 个人开发者: 快速生成小工具原型、API 集成、自动化脚本
- 技术爱好者: 探索多 Agent 协作、AI 工具调用、知识管理

**核心差异化**:
- Workspace-first: 以工作空间为中心，不是以工作流为中心
- 本地优先: 不需要账号、不需要自己部署服务器
- 中文优先: Agent 人设和 UI 全中文
- QQ 群聊式圆桌: 直觉化的多 Agent 讨论体验

## 2. 技术架构

### 2.1 当前阶段: Web MVP (v0.3.0)

```
Frontend (React + Vite + TypeScript)
  ↕ HTTP/SSE
Backend (Node.js + TypeScript)
  ↕ HTTP
Cloud AI APIs (OpenAI / Anthropic / DeepSeek / Qwen / Ollama)
```

**数据库**: 当前用 JSON 文件持久化 (.agent-data/)，后续升级 PostgreSQL
**检索**: 当前关键词匹配，后续升级 BM25 + 向量混合检索

### 2.2 未来阶段: 桌面端 (v0.4.0)

```
Tauri Shell (Rust)
  ├─ Frontend: React Webview
  ├─ Backend: Python 子进程 (PyO3)
  ├─ System: 文件系统 / 终端 / Git / 通知
  └─ Database: SQLite → PostgreSQL
```

### 2.3 未来阶段: 移动端 (v0.5.0)

```
Capacitor Shell
  ├─ Frontend: React (精简版)
  ├─ Storage: 内嵌 SQLite
  └─ Features: 对话 + 圆桌
```

## 4. Agent 编排引擎 (S1)

### 4.1 Agent 定义扩展

```typescript
interface AgentConfig {
  id: string;
  role: AgentRole;
  name: string;
  avatar: string;            // emoji 或图片 URL
  avatarType: "emoji" | "image";
  goal: string;              // 借鉴 CrewAI: Agent 的目标
  backstory: string;         // 借鉴 CrewAI: Agent 的背景故事
  systemPrompt: string;
  model?: string;
  providerId?: string;
  tools: string[];
  color: string;
  custom?: boolean;          // 是否用户自定义
}
```

### 4.2 三种编排模式

**Sequential (顺序模式)**:
```
Agent A → Agent B → Agent C
每个 Agent 完成后，输出作为下一个的输入
```

**Hierarchical (层级模式)**:
```
         主持 Agent
        /    |    \
   Agent A  Agent B  Agent C
主持分配任务，收集结果，综合输出
```

**Roundtable (圆桌模式)**:
```
Agent A ↔ Agent B ↔ Agent C
    ↕         ↕         ↕
自由讨论，轮流发言，投票表决
```

### 4.3 工具调用系统

Agent 可以通过 function calling 主动调用工具:
- 文件读写 (read_file, write_file, list_files)
- 命令执行 (run_command)
- 网络请求 (fetch_url)
- 知识检索 (search_knowledge)
- 记忆读写 (read_memory, write_memory)

每个工具调用需要经过审批系统 (低风险自动批准，高风险需用户确认)。

## 5. 记忆系统 (S3)

### 5.1 分层架构 (移植腾讯)

| 层级 | 名称 | 存储 | 生命周期 |
|------|------|------|---------|
| L1 | 对话记忆 | 内存 | 对话结束即丢 |
| L2 | 工作记忆 | 内存 | 任务结束即丢 |
| L3 | 事实记忆 | 持久化 | 长期保留 |
| L4 | 情景记忆 | 持久化 | 长期保留 |
| L5 | 语义记忆 | 向量存储 | 长期保留 |
| L6 | 程序记忆 | 持久化 | 长期保留 |
| L7 | 记忆压缩 | 摘要 | 定期更新 |
| L8 | 记忆遗忘 | 衰减 | 基于时间和重要性 |

### 5.2 记忆检索

混合检索: BM25 关键词匹配 + 向量相似度 + 时间衰减 + 重要性权重

## 6. 代码生成流程 (S4)

### ChatDev 式阶段流程

```
阶段 1: 需求分析 (产品 Agent)
  输入: 用户描述
  输出: 需求文档
  交互: 3-5 个澄清问题

阶段 2: 技术设计 (架构 Agent)
  输入: 需求文档
  输出: 技术方案 (技术栈、架构图、API 设计)
  交互: 用户确认或修改

阶段 3: 代码生成 (开发 Agent)
  输入: 技术方案
  输出: 项目文件
  交互: 实时显示生成进度

阶段 4: 运行修复 (循环)
  输入: 项目文件
  输出: 可运行项目
  流程: 运行 → 测试 Agent 发现 bug → 开发 Agent 修复 → 重复

阶段 5: 文档生成 (文档 Agent)
  输入: 项目文件
  输出: README、架构文档、使用说明

阶段 6: 最终审查 (评审 Agent)
  输入: 全部产出
  输出: 审查报告
```
